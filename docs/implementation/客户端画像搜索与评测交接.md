## 一、云端画像、特征空间与群体结果缓存设计

### 1.1 双端 SQLite 新增缓存结构

Windows (`client/electron/database-worker.cjs`) 与 Android (`HappyGitDbHelper.java` 升级 `DATABASE_VERSION = 4`，无损保留 v1–v3 历史数据，`LocalRepository.java`) 新增以下本地表：

1. **`cloud_portraits`**（按 `account_id` 唯一主键隔离）：
   - 绑定同代版本元数据：`subject_id`、`analysis_epoch`、`status`（`ready | pending | stale | empty | analysis_disabled | unbound`）、`model_version`、`feature_space_version`、`catalog_snapshot_id`、`generation_id`、`reference_time`、`generated_at`、`processed_through`、`input_digest`。
   - 持久化同代正文：`portrait_json`、`search_plan_json`、`feature_space_json`、`coverage_json`、`input_versions_json`、`is_fixture` 与真实拉取时间 `fetched_at`。
2. **`cloud_cohorts_cache`**（群体聚合统计缓存）：
   - 记录 `model_version`、`generation_id`、`source_kind`（区分 `real_production` 与 `synthetic`）、`reference_time`、`generated_at` 与 `cohorts_json`。

### 1.2 同构 8192 维投影与摘要校验

- **摘要核对**：`CloudService.fetchVerifiedFeatureSpace(token, featureSpaceVersion)` 在下载特征空间后校验其 SHA-256（兼容带末尾 `\n` 与无末尾换行两类规范化序列化）是否等于 64 位 `featureSpaceVersion`；若不一致抛出 `FEATURE_SPACE_DIGEST_MISMATCH` 并拒绝应用。
- **与 `data-platform Vectors.java` 对齐的客户端同构投影**（`client/shared/recommendation/features.js`）：
  - 分词器 `tokenizeTechnicalNfkcBigram` 采用与 `Vectors.tokens` 完全一致的 NFKC 归一化、专有词识别（`c++`、`c#`、`.net`、`node.js`）、英文/数字词元及中文双字 bigram 与停用词集合。
  - `projectRepositoryToFeatureSpace` 对训练目录之外的新搜索项目采用精确的区块 L2 尺度（`language = 0.20`、`topic = 0.30`、`text = 0.50`）与 `normalizeDenseToSparse(sum, 256)` 稀疏归一化。
  - **未知缺失真实保留**：不在已发布特征空间词表内的语言、topic 与词项如实记录在 `missingFeatures`，绝不编造虚构向量坐标，也不在 `recommendation.worker.js` 中重新拟合不兼容词表。

2. **`GET /api/v2/me/search-plan`**（与 `generationId`、`analysisEpoch` 对齐）

## 三、本地排序与事件接续规则

1. **严格区分 `acceptedThrough` 与 `processedThrough`**：
   - 上传事件获得 `acceptedThrough` ACK 后，本地在 `deviceSeq > processedThrough` 区间内的有效 `open` 事件仍会通过 `readUnprocessedEvents(accountId)` 被纳入近期增量上下文（`buildRecentIncrementContext`）；
   - 仅当云端画像发布且 `processedThrough` 推进并覆盖该序号后，对应事件才停止作为长期画像之外的本机增量，避免重复计权。
2. **快照不可变与迟到保护**：
   - `createSnapshot` 一次性冻结 `account_revisions` + `analysisEpoch` + `processedThrough` + `portraitGenerationId` + `portraitModelVersion` + `featureSpaceVersion`；
   - Worker 不访问数据库或网络，返回提交前由原生 `commitRecommendation` 校验所有版本号与单次消费标记，任何隐藏反馈、分析关闭、画像更新或账号切换都会使旧快照/旧任务结果失效；
   - `saveCloudPortrait` 拒绝接受 `processedThrough` 或 `generatedAt` 落后于当前已缓存版本的迟到结果，并在 `analysis_epoch` 变更或 `analysisEnabled = false` 时立刻隔离旧范围缓存。
3. **固定批次分页**：
   - 列表滚动/“加载当前批次更多项目”仅从当前已提交的 `recommendation_batches` 分页读取（`listRecommendation`），不在分页过程中重算排序。

## 四、双端搜索、界面展示与能产生回流的操作步骤

1. **有界画像驱动搜索（`recall.js` + `ipc-router.cjs` + `HappyGitPlugin.java`）**：
   - 将云端 `searchPlan`（或本地降级画像）通过受控规则构造安全查询串并限制单轮**最多 4 条查询、总计最多 8 页**，按 `repoId`/`canonicalKey` 去重且保留完整 Repository DTO；支持通过“探索下批项目”递增游标，不将局部结果声称为全站检索完成。
2. **项目卡片证据字段与关注度规范（`normalize.js` + `TrendingView.vue`）**：
   - 提取并展示用途摘要（`purposeCue` + 来源：`description`/`readme`/`topics`）、README 实际安装线索（`installCue`）、许可证（`licenseSpdx`）、最近维护时间（`pushedAt`/`updatedAt`）、GitHub 原页链接；Star 统一命名为**“关注度 ⭐”**，不冒充质量评分。
3. **个人空间与群体分布页面（`ProfileView.vue`）**：
   - 个人页真实区分 `ready` / `pending` / `stale` / `empty` / `analysis_disabled` / `unbound` 状态、展示学习方向权重、来自个人输入的可追溯 `evidenceRepos` 及 `processedThrough / acceptedThrough` 进度；
   - `群体分布` 页签仅展示聚合统计（样本数、来源 `sourceKind`、生成时间与 `<10` 抑制说明），不把个人标签冒充群体分析。
4. **能触发服务端回流再训练的客户端操作路径**：
   1. 在“设置 -> 云端分析与隐私”绑定与当前 GitHub 登录一致的云端账号，确认“允许服务端兴趣分析与行为上传”已开启；
   2. 在“发现项目”浏览并打开数个公开项目（间隔 `> 30s`），触发 `open` 按次行为入队并上传至 `/api/v2/events/batches`；
   3. 对感兴趣项目执行 `Star` / `取消 Star` 触发 `/api/v2/me/collections`（`stars`）修订上传；
   4. 在“为你推荐”卡片点击“隐藏”记录显式负反馈（可连同 `manualTags` 经设置同步）；
   5. 等待成员甲归档归集并发布第 1 版个人画像后，点击“刷新云端画像”观察 `processedThrough` 推进及旧未处理增量的接续退出，再用后续产生的新浏览配合 A 侧完成第二轮模型再训练与换版验证。
