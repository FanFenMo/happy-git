# 云端身份与数据接入

本页固定第一轮服务端实现协议，基线为 develop `5e46112`。API 位于 `/api/v2`，由 `cloud` profile 提供，独立于本机 GitHub 网页会话。该协议已有本分支代码，部署和联调状态见[交接记录](服务端数据接入交接.md)。画像与搜索计划仍在第二轮实现。

客户端调用 `POST /auth/github/begin`，正文为 `{"codeChallenge":"S256(verifier) 的 base64url"}`。返回 challengeId、authorizationUrl、expiresAt 和 intervalMs。原生层保存 43—128 位 verifier，打开授权网址，再以 `{"challengeId":"...","codeVerifier":"..."}` 调用 `POST /auth/github/poll`。state 为 pending、authenticated、denied、consumed 或 expired。authenticated 同时返回 accessToken、refreshToken、expiresAt、subjectId 和 accountId。服务端用 GitHub `/user` 核验身份，仅返回应用凭据，不把 GitHub token 下发给云端业务调用方。客户端核对 accountId 与本机网页会话一致后启用上传。

应用调用携带 `Authorization: Bearer <accessToken>`。accessToken 有效一小时；`POST /session/refresh` 接收 refreshToken，原子撤销旧凭据并返回新一对凭据，保留设备绑定，refreshToken 有效三十天。`POST /session/logout` 撤销当前应用会话。原生凭据存储由客户端实现。授权回调单独使用 `GITHUB_CLOUD_CALLBACK_URL`，部署值为 `/api/v2/auth/github/callback` 的完整 HTTPS 地址。

`GET /me/preferences` 返回 subjectId、analysisEnabled、analysisEpoch、revision、manualTags、hiddenRepoIds。新账号默认关闭分析，epoch=1、revision=0。`PUT /me/preferences` 正文必须含 operationId、expectedRevision、analysisEnabled、manualTags、hiddenRepoIds，使用明确设置值。同一 operationId、相同正文重试返回原结果；内容不同返回 409 IDENTITY_CONFLICT。revision 是整个账号的设置与集合共享修订，变更后必须使用新值。analysisEnabled 切换使 epoch 增加，旧流和旧归档范围失效。

`POST /devices/register` 接收 `{"installationId":"本安装生成并保存的随机标识"}`。安装标识在账号下稳定；同会话只绑定一个设备。返回 deviceId、streamEpoch、analysisEpoch、acceptedThrough、exportedThrough、processedThrough、serverTime 与 preferences。同一设备同一 epoch 返回同一流；清理或设置换代后重新注册取得新流。设备和账号归属从会话读取，事件请求不得自行声明可信 subjectId 或 deviceId。

`POST /events/batches` 的固定结构如下。所有时间为 UTC 毫秒整数，序号和修订在 JS 安全整数内。每批为一个流，最多 500 条，未压缩 UTF-8 请求体上限 1 MiB，要求 application/json，不接收压缩请求。

```json
{"requestId":"batch-uuid","streamEpoch":"注册得到的UUID","analysisEpoch":2,"firstSeq":1,"events":[{"recordKind":"open","schemaVersion":"1.0.0","eventId":"event-uuid","streamEpoch":"注册得到的UUID","deviceSeq":1,"analysisEpoch":2,"repoId":"123","occurredAt":1794096000000,"source":"browse","entrySource":"trending","payloadHash":"64位小写十六进制SHA256"}]}
```

摘要复用旧契约：紧凑 JSON 数组 `[schemaVersion,eventId,streamEpoch,deviceSeq,analysisEpoch,repoId,occurredAt,source]` 的 UTF-8 SHA-256，无 BOM、空格、换行。source 支持 browse/repo_open，以及旧契约的 recommended/trending/history/stars/owned/detail/open；entrySource 可另存原入口。entrySource 不进入旧版摘要，但也会参与服务端的同身份内容核对。服务端只导出 source=browse 或 repo_open，不以 Star 集合伪造浏览。事件的30秒有效性去重由原生端在本地事务内完成。

请求内 deviceSeq 从 firstSeq 连续递增。允许从已确认范围开始重放，新增记录必须紧接 acceptedThrough。缺号返回 409 SEQUENCE_GAP；eventId 在账号内唯一，流序号也唯一。同身份相同内容返回既有确认，冲突为 409 IDENTITY_CONFLICT；请求整体在同一事务提交，发生冲突不接收一半批次。`discard` 仅包含 recordKind、eventId、deviceSeq、payloadHash，可占据已从本地删除正文的序号，不产生训练事件；不能用它改写已有正文。已接受事件的未来时间超过服务端五分钟时以首次 receivedAt 为 effectiveAt，重发保持原修正值。

响应返回 deviceId、streamEpoch、analysisEpoch、acceptedThrough、exportedThrough、processedThrough、serverTime 和 timeAdjustments。timeAdjustments 为本批已有或新增 open 的 eventId/effectiveAt。acceptedThrough 表示事务持久接收；exportedThrough 表示已闭合并登记 HDFS 文件；processedThrough 本轮保持0，由后续画像发布推进。客户端按 processedThrough 接续本机增量，不能根据 acceptedThrough 清除未计算增量。

`PUT /me/collections` 接收 operationId、expectedRevision、analysisEpoch、collectionKind（stars/owned）、complete、observedAt 和 repoIds。repoIds 为稳定项目ID数组，上限20,000。每次输入登记新的共享 revision；complete=false 返回 activated=false，保留上一份完整集合。unknown 不上传成空的完整集合。完整空数组明确表示已完整读取且为空。

`POST /me/analysis/reset` 接收 operationId、expectedRevision。它使 epoch 增加，清空云端偏好和集合、移除 MySQL 旧事件正文并使旧归档失效；保留最小去重回执。启用状态保持当前设置。客户端丢弃旧范围上传队列并重新注册。读取和训练准备必须按当前有效 subjectId/analysisEpoch 筛选；归档历史不得绕过授权范围直接进入训练。关闭分析返回 ANALYSIS_DISABLED，旧代上传返回 STALE_ANALYSIS_EPOCH。

错误响应使用 HTTP 状态和 `{"code":"稳定错误码","message":"说明"}`。400 表示字段、摘要或序号格式无效；401 SESSION_REQUIRED/SESSION_EXPIRED 表示应用会话不可用；403 INVALID_PROOF/ADMIN_REQUIRED 表示证明或服务凭据无效；409 还包括 REVISION_CONFLICT、DEVICE_STREAM_REQUIRED、DEVICE_ALREADY_BOUND；413 BODY_TOO_LARGE 表示实际请求字节超限。客户端重新读取设置或重新授权后再处理409，不盲目更改稳定事件身份。

内部 `/internal/exports/prepare`、`/internal/exports/{exportId}`、`/internal/exports/{exportId}/commit` 由 data-platform 使用独立 HG_CLOUD_ADMIN_TOKEN 调用。prepare 冻结 subject、最新完整集合和一个设备流最多500条记录及明确序号范围；discard 只影响水位。平台按 records 原顺序输出紧凑JSONL，每行带换行，摘要和字节数需与冻结响应一致。只有闭合 HDFS 文件的摘要、字节数、记录数一致，commit 才推进 exportedThrough。commit重发返回原登记。scope 换代使未归档批次也失效。`GET /internal/analysis-scopes` 提供仍有效的 subjectId/analysisEpoch，为第二轮准备输入时的强制筛选依据。
