# 新 HappyGit 第一版接口与数据契约

本文件是[服务端](服务端详细设计.md)、[Hadoop](Hadoop计算实现详解.md)和[客户端](客户端详细设计.md)共同使用的函数参数字典，版本 1.0，2026-10-29。类型用 TypeScript 记法表达，客户端仍使用 JavaScript/JSDoc；服务端使用 Java DTO，Hadoop 使用 Java 8 POJO/Writable。接口结构的业务约束在原 SDD 基础上细化，以下新增字段均为待实现设计。

## 1. ID、版本与时间

`accountId` 是 GitHub 数字用户 ID 的字符串，内部 `subjectId` 是服务端用户 UUID；公开 API 不接受客户端自选 subjectId。`repoId` 始终为字符串，不能用 `owner/name` 替代稳定身份。所有网络时间为 UTC 毫秒整数，窗口统一为 `windowStart < effectiveAt <= referenceTime`。业务序号限制在 JavaScript 安全整数范围内；到边界时结束旧流并建立新流，不静默截断。

`modelVersion=mr-content-v2` 描述计算规则；`featureSpaceVersion` 是不可变特征制品原始字节的 SHA-256；`catalogSnapshotId` 标识项目语料；`generationId` 标识一次原子发布；`batchId` 标识该次服务端候选包；`clientBatchId` 标识本机最终排序。`inputId` 绑定一次本机计算快照，`contextId` 绑定当前登录上下文，它们不能用生成时间互相替代。

第一版继续使用 `schemaVersion="1.0.0"` 标识事件结构。推荐包与原生计算快照补充 `contractVersion="2.1.0"`，用于区别原 `content-v1` payload。这只是传输契约版本，不改变上述模型版本。

## 2. 事件到底长什么样

```ts
type OpenRecord = {
  recordKind: 'open';
  schemaVersion: '1.0.0';
  eventId: string;
  deviceSeq: number;
  streamEpoch: string;
  analysisEpoch: number;
  repoId: string;
  occurredAt: number;
  source: 'recommended' | 'trending' | 'history' | 'stars' | 'owned' | 'detail' | 'open';
  payloadHash: string;
};
type DiscardRecord = {
  recordKind: 'discard';
  eventId: string;
  deviceSeq: number;
  payloadHash: string; // 原 open 正文的摘要；正文已经从本机删除
};
type EventBatch = {
  streamEpoch: string;
  analysisEpoch: number;
  firstSeq: number;
  events: Array<OpenRecord | DiscardRecord>;
};
type IngestAck = {
  deviceId: string;
  streamEpoch: string;
  acceptedThroughSeq: number;
  exportedThroughSeq: number;
  serverTime: number;
  timeAdjustments: Array<{eventId: string; effectiveAt: number}>;
};
```

一批只含一个设备流，最多 500 条、未压缩 UTF-8 请求体最多 1 MiB。`deviceId` 由已绑定应用会话决定，`subjectId` 由认证决定，二者不由正文声明。open 的 streamEpoch/analysisEpoch 必须与批头相同。discard 不带 repoId、occurredAt 或浏览正文。

摘要编码统一为紧凑 JSON 数组的 UTF-8 字节，固定顺序为 `[schemaVersion,eventId,streamEpoch,deviceSeq,analysisEpoch,repoId,occurredAt,source]`。ID/source 的合法字符集和版本固定，数值输出十进制整数；Java 与 JS 均不转义 `/`，无 BOM、无换行或多余空格。该设计避免依赖对象字段遍历顺序。服务端对 open 重算摘要；discard 只能用原摘要核对已有记录或保存终结凭据，不伪造被删内容。

接收时保存 `receivedAt`。若 `occurredAt > receivedAt+300000`，`effectiveAt=receivedAt`，否则使用 occurredAt；重复接收保持原 effectiveAt。接收 ACK 可以超过本次请求最后序号，因为服务端可能已经处理后续范围；客户端只终结本地确实存在且不超过该连续水位的记录。

## 3. 项目向量与用户画像

```ts
type SparseVector = {
  dimension: 8192;
  indices: number[]; // 严格递增，0..8191
  values: number[];  // 等长、正的有限数；零项不存
};
type FeatureSpace = {
  schemaVersion: '1.0.0';
  modelVersion: 'mr-content-v2';
  dimension: 8192;
  languageTerms: Array<{term: string; index: number}>;
  topicTerms: Array<{term: string; index: number}>;
  textTerms: Array<{term: string; index: number; df: number; idf: number}>;
  documentCount: number;
  tokenizer: {
    version: string; unicodeVersion: string;
    technicalTerms: string[]; aliases: Record<string,string>;
    stopwords: string[]; chineseTerms: string[];
    normalizationCases: Array<{input: string; tokens: string[]}>;
  };
  weights: {language: 0.20; topic: 0.30; text: 0.50};
  limits: {readmeCodePoints: 8000; repositoryNnz: 256; portraitNnz: 512};
};
```

制品不在正文内嵌自己的哈希，否则产生自引用。发布器将 FeatureSpace 序列化为固定 UTF-8 文件后计算摘要，版本放在 Manifest、URL 和响应头中。客户端对下载字节先校验摘要、再解析，不能解析后重新序列化再比较。语言、topic、文本的坐标分别占 `[0,127]`、`[128,1151]`、`[1152,8191]`；未使用位置为零。

普通 Repository DTO 沿用当前 `client/shared/github-page/normalize.js` 的字段：repoId、canonicalKey、owner、name、fullName、htmlUrl、description、primaryLanguage、topics、starCount、forkCount、countPrecision、visibility、isArchived、isFork、licenseSpdx、createdAt、updatedAt、fetchedAt。README 只随详情或特征输入传输。候选必须携带完整卡片 DTO，不能拿只剩 `vector` 的对象交给 Vue。

```ts
type Candidate = {
  repoId: string;
  repository: RepositoryDTO;
  vector: SparseVector;
  serverSimilarity: number | null;
  qualityScore: number | null;
  freshnessScore: number | null;
  recallSource: 'similarity' | 'popular';
  reasons: Array<{kind: string; tag?: string; evidenceRepoIds?: string[]}>;
};
type ProcessedMark = {
  deviceId: string; streamEpoch: string; processedThroughSeq: number;
};
type Profile = {
  vector: SparseVector;
  languages: Record<string,number>;
  topics: Record<string,number>;
  topInterests: Array<{tag: string; score: number; evidenceRepos: string[]}>;
  evidenceCount: number; // 有可用项目向量且权重>0的不同项目数，不含手动标签
  sourceCoverage: {
    windowStart: number; windowEnd: number;
    browseEventCount: number;
    usableEvidenceRepoCount: number;
    missingFeatureEventCount: number;
    starsComplete: boolean; ownedComplete: boolean;
    activityObservedFrom: number | null; activityObservedTo: number | null;
  };
};
```

`qualityScore` 在第一版只是公开关注度的代理：当 starCount 已知且非负时为 `min(log1p(starCount)/log(10001),1)`，否则为 null。它不表示代码质量鉴定。`freshnessScore=2^(-max(0,referenceTime-updatedAt)/86400000/180)`，updatedAt 缺失时为 null。两项在 J06/J12 用固定 referenceTime 计算，客户端不随刷新时间重新改变它们。

## 4. 一个推荐包是一个不可拆开的输入版本

```ts
type RecommendationBundle = {
  contractVersion: '2.1.0';
  accountId: string;
  generationId: string; batchId: string;
  modelVersion: 'mr-content-v2'; featureSpaceVersion: string;
  catalogSnapshotId: string;
  datasetKind: 'real' | 'synthetic';
  mode: 'personalized' | 'cold_start';
  generatedAt: number; expiresAt: number;
  privacyRevision: number; analysisEpoch: number;
  preferenceRevision: number; feedbackRevision: number;
  processedThrough: ProcessedMark[];
  profile: Profile;
  candidates: Candidate[]; // 去重后最多300项
  coverage: 'complete' | 'partial';
};
```

公共包沿用以上公共字段，mode 为 public，省去 accountId、profile、隐私/偏好修订和 processedThrough。客户端为公共包建立本机账号作用域的使用快照，基础向量为空、处理水位为空；没有账号的游客只显示公共顺序，不生成伪用户画像。

`coverage=complete` 表示已返回目标 300 条，数量不足或即时过滤导致减少为 partial；它不代表“扫描到了 GitHub 全站”。空画像但有手动词表外标签时仍为 cold_start。`generatedAt` 是该 generation 产物确定时间，`expiresAt=generatedAt+24h`，读取接口不能每次续期。一次发布若已过有效期应重跑，不能发布后假装刚生成。

目前的 API 和原生桥有两种包裹。HTTP 正常响应为 `{requestId,data}`，错误为 `{requestId,error:{code,message,retryAfterMs?}}`；原生桥统一返回 `{ok:true,data}` 或 `{ok:false,error:{code,message,retryAfterMs?}}`。内部仓储返回领域值或抛出业务异常，不再返回第二层 `{ok:false}`，由原生路由一次转换，避免外层成功、内层失败却被页面当成功。

## 5. 函数间共享的运行输入

`InputManifest` 包含 runId、generationId、datasetKind、referenceTime、windowStart、modelVersion、catalogSnapshotId、可选复用的 featureSpaceVersion、公开集合/偏好/隐藏/隐私快照、所有输入路径与摘要，以及每条流的 previousProcessedThroughSeq 和 exportedThroughSeq。首次为 0，后续计算既要读 90 天行为事实，也要核对新增序号范围的终结凭据。旧处理前缀不等于可删除仍在窗口内的行为事实。

`UserSeed` 是每个允许分析账号的一条记录，含 subjectId、manualTags、各 revision、analysisEpoch、集合完整性、活动观测范围及设备流边界。即使用户没有浏览、没有 Star、没有仓库，J09 也能从种子输出一个空画像。公开集合中只存已完成的一代；不完整新采集不能覆盖旧完整集合。

`Evidence` 以 `(subjectId,repoId)` 唯一，携带 validOpenCount、lastCountedOpenAt、activityCount、lastActivityAt、isCurrentlyStarred、isOwned、hidden 和计算后的 weight。`Contribution` 携带 subjectId、repoId、weight、项目向量、语言、topics、该项目使用/忽略的事件数。两者的差别是后者已经与 J06 的特征匹配。

本机 `RerankSnapshot` 包含 inputId、contextId、accountId、固定 now、serverBatchId、generationId、featureSpaceVersion、catalogSnapshotId、privacyRevision、analysisEpoch、deltaRevision、bundleCacheRevision、manual/hidden/owned 修订、基础向量、候选、FeatureSpace、最近 7 天未覆盖事件、同版项目特征及最近 24 小时已看项目集合。完整输入由原生端一次冻结；Worker 不再读取 Date.now、Pinia、SQL 或网络。

具体传入 Worker 的结构如下。inputVersions 由原生写入并保存，Worker 仅原样带回。`localEvents` 可以包含本机查询到的近期候选事件，最终窗口和处理水位筛选由 selectDeltaEvents 完成，因此不会因 SQL 与 JavaScript 各自实现一种窗口而产生分歧。

```ts
type LocalEvent = {
  eventId: string; accountId: string; localSeq: number;
  recordKind: 'open'; deleted: boolean;
  repoId: string | null; canonicalKey: string;
  occurredAt: number; effectiveAt: number | null;
  analysisEpoch: number;
  deviceId: string | null; streamEpoch: string | null; deviceSeq: number | null;
};
type InputVersions = {
  serverBatchId: string; generationId: string;
  catalogSnapshotId: string; featureSpaceVersion: string;
  privacyRevision: number; analysisEpoch: number;
  deltaRevision: number; bundleCacheRevision: number;
  preferenceRevision: number; hiddenRevision: number; ownedRevision: number;
};
type RerankSnapshot = {
  inputId: string; contextId: string; accountId: string; now: number;
  purpose: 'rerank_v2'; modelVersion: 'mr-content-v2'; contractVersion: '2.1.0';
  inputVersions: InputVersions;
  analysisEpoch: number; // 等于inputVersions中的值，便于纯函数读取
  baseVector: SparseVector; profile: Profile | null;
  processedThrough: ProcessedMark[];
  featureSpace: FeatureSpace; candidates: Candidate[];
  localEvents: LocalEvent[];
  eventFeatures: Array<{eventId: string; vector: SparseVector | null;
    repository: RepositoryDTO | null; metadataHash: string | null}>;
  hiddenRepoIds: string[]; ownedRepoIds: string[]; recentOpenedRepoIds: string[];
};
```

未开启云端分析时，本机 scope 的 privacyRevision/analysisEpoch 仍由 cloud_account_state 保存，公共包不需要伪造这两项。快照中的这些值来自本机当前授权状态；已启用且有正式包时同时要求包与本机已知状态一致。词表/目录等版本来自当前选中的个人或公共包。

## 6. 对原 SDD 的实现补充

原数据库 SDD 已通过 `archive_batch_id` 支持归档后清除 open 正文，并保留 effective_at。本版再补充 `time_adjusted`，用于正文清理后仍能在重复 ACK 中返回原时间修正。沿用的正文约束如下；archive_batch_id 必须引用已提交的归档批次，该跨行状态由清理事务核验。

```sql
CHECK (
  (record_kind = 'discard' AND payload_json IS NULL)
  OR
  (record_kind = 'open'
   AND (payload_json IS NOT NULL OR archive_batch_id IS NOT NULL))
)
```

这是对既有设计的实现细化，不是对现有生产库的迁移操作。open 已归档后仍保留 eventId、序号、摘要、effectiveAt 与修正标记，因此重复请求能够核对原内容和返回相同时间修正。

原 SDD 中“原生保存 inputId”的行为需要实际表承载，SQLite v3 增加 `compute_inputs(input_id,account_id,context_id,versions_json,snapshot_json,created_at,consumed_at)`。只保留当前账号少量未消费输入，提交成功后标记 consumed，过期输入可删除。增加 `client_account_runtime(account_id,context_id,delta_revision,bundle_cache_revision,active_bundle_id,visible_client_batch_id,pending_client_batch_id)` 承载原子切换与比较。这些字段不能只保存在 Worker 回传值里。

`local_rank_snapshots` 同时保存 input_id，并对 `(account_id,input_id)` 建唯一约束；同一输入的提交回执由此可恢复。已消费输入可清 snapshot_json 但保留短期身份回执。本机删除历史或云端重置时，同事务删除包含相关行为正文的 compute_inputs 快照并使排序结果失效，不能只删除事件主表而留下旧计算输入副本。

同一 batchId 的服务器候选可能因新隐藏或仓库可见性修正而减少，服务端 batchId 不变，但本地 `bundleCacheRevision` 必须增加。否则仅比较 batchId 无法阻止旧 Worker 结果覆盖新的候选集合。`historyEnabled=false` 时，本机增量和已看降权均停用；云端长期画像是否继续使用既有数据由独立云端设置控制。

补充 `oauth_challenges` 支持一次性授权领取，补充 `public_ranking_batches/items` 存放没有 user_id 的 J12 输出，补充 `job_attempts` 保存重试 application/job 身份，补充 `account_mutations` 保存 mutationId、请求摘要与结果修订。公共候选不硬塞入具有 user_id 外键的个人批次表。HTTP preferences 对云端分析开关同时检查 expectedPrivacyRevision，避免两个设备以旧设置重新开启刚被撤回的授权。

本机另加 `client_mutation_outbox(account_id,mutation_id,kind,payload_json,payload_hash,state,next_attempt_at)` 保存离线隐藏/设置意图。同一 mutationId 内容固定；用户后续改变意图生成新的 mutationId。云端关闭分析排在浏览同步之前发送。事件 outbox 的 state 为 pending/acknowledged，是否 discard 由 record_kind 表达，不能把“已发送”误当成画像已覆盖。

## 7. 用一个小例子核对双方理解

假设设备 A 的 G1 处理水位为 100，A 本机有 seq 101、102，设备 B 有独立的 seq 8。A 的本机增量只从 A 的本地事件构成，不读取 B 的明细；A 上传成功到 102 后仍使用 101、102，直到新画像包含 A 流水位 102。设备 B 的数字 8 不与 A 的 102 比较。

假设某本机事件没有上传序号，代表发生时未授权上传。它在最近 7 天内可参与本机调整，但不因后来启用同步而补传。若该用户清空云端浏览，analysisEpoch 增加，旧流停止，所有旧代本机微调事件也按清空范围移除；之后产生的事件属于新流。以这些例子检验代码，比增加与业务无关的异常检测更有价值。
