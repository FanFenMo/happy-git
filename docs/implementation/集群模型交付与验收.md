# 集群模型交付与集中验收

本轮从第二轮已验收 develop 开始，A 维护 server、data-platform、Ubuntu 配置与服务端运行工具，实现分支为 `feature/cluster-model-release`。功能分支进行编译、配置生成和静态自查；下面的真实部署、YARN 训练、故障接续及正式模型发布，在本轮相关功能合入 develop 后集中执行。B 继续负责正式数据、独立大模型评测和双端交付。

## 版本包与节点安装

维护者填写 `deploy/ubuntu/inventory.two-host.example.json` 或三节点清单，指定主机名、实际地址、YARN 内存与 vcores、安装根、数据根、服务用户、API 节点和训练协调节点。版本安装入口使用专用 `/opt/...` 与 `/var/lib/...` 目录。API 使用 JDK17，Hadoop 和数据平台使用 JDK11。api.envFile 指定私有业务配置位置；真实凭据放在目标主机的 cloud.env/platform.env，环境样例只包含字段与空值。

数据平台与服务端分别在对应 JDK 下执行 `mvn -f data-platform/pom.xml -Dmaven.test.skip=true package`、`mvn -f server/pom.xml -Dmaven.test.skip=true package`。形成已提交的源码版本后打包：

```bash
python3 tools/server_release.py package \
  --inventory deploy/ubuntu/inventory.actual.json \
  --platform-jar data-platform/target/happygit-data-platform-1.0.0.jar \
  --server-jar server/target/happygit-server-1.0.0-SNAPSHOT.jar \
  --release-id cluster-model-版本名 --output output/server-releases
```

输出包含节点 XML、systemd 角色与定时器、两个 JAR、启动脚本、安装与切换入口、运维工具和运行协议。release-manifest.json 记录源码提交与各文件的字节数/SHA-256，压缩包旁另有 .sha256。打包时要求源码工作区已提交，输出中的验收状态仍为功能分支编译完成。配置生成与打包不连接远程节点。

将完整压缩包和校验文件传至指定 Ubuntu 节点，先用 `sha256sum -c <压缩包.sha256>` 核对，再解压。在解压目录执行：

```bash
sudo bash deploy/ubuntu/install-release.sh \
  "$PWD" hg-1 /opt/happygit-runtimes/hadoop-3.4.2 \
  /opt/happygit-runtimes/jdk11 /opt/happygit-runtimes/jdk17
```

没有 API 角色的节点省略最后一个 JDK17 参数。安装器将版本保存到 releases/版本，保留已有 HDFS 目录、私有环境与 ZooKeeper myid，准备运行时符号链接。安装过程不启动服务，也不初始化或格式化存储。

维护者配置实际数据库、OAuth 回调、共享 ZooKeeper 认证、数据平台到业务 API 的地址及服务凭据。协调节点的归档、画像调度和训练定时器读取同一份 platform.env；训练清单由 conf/learning-batch.json 指定。先检查数据包路径、referenceTime 与账号授权范围，再启用定时任务。

切换前先停止明确选定的提交定时器和受影响应用进程，保存当前任务及模型指针，然后选择本机角色：

```bash
sudo bash deploy/ubuntu/activate-release.sh /opt/happygit cluster-model-版本名 hg-1
```

切换器备份原公开配置，安装该节点配置和单元，更新运行版本信息，原子切换 current 代码链接并重新加载 systemd；之后由维护者启动选定单元。回退代码使用同一命令选择已安装旧版本，数据库迁移兼容性单独核对。模型回退使用现有 learning-model --action rollback，保留实际原因及 expectedRevision。私有配置、归档和模型历史不参与代码目录切换。

## 固定版本结果交给 B

先通过 learning-prepare 冻结数据包，按第二轮入口训练并取得实际模型描述符。`deploy/ubuntu/model-export.example.json` 给出导出协议：dataset 为固定数据描述符，model 为已验证模型描述符，split 固定用户划分，mode 为 baseline/learned/both。可选 referenceTime 必须等于冻结数据时间；subjectIds 为空表示该划分的全部用户。userBlocks 采用稳定用户哈希，最多 64 块，每块独立推断。

```bash
/opt/happygit/bin/data-platform learning-export \
  --file /var/lib/happygit/protocols/固定协议.json \
  --output hdfs://实际名称服务/happygit/experiments/独立运行目录 \
  --local-output /var/lib/happygit/exports/独立运行目录
```

Hadoop 与本地输出目录须为新目录，保留每次运行及失败证据。命令产生 baseline.jsonl、learned.jsonl 和 run-manifest.json，运行状态须为 completed 才进入正式对比。基线固定为 rules-mr-30d-3-1.5-v1，浏览半衰期 30 天、Star 权重 3、owned 权重 1.5；学习模型使用实际选参。两者读取相同证据、目录和已冻结特征空间，不在推断时重新拟合。该基线与 B 自有本地基线分别保留，报告标注实际方法。

结果每行包含 subjectId、method、modelVersion、featureSpaceVersion、catalogSnapshotId、referenceTime、兴趣分布、Top 标签及用户实际证据引用。运行清单分别记录原数据集规模与选中范围的原始证据来源计数，另有协议摘要、模型、分块、用户数、预测数量、向量规模、耗时、文件摘要和 jobs。包含真实客户端授权范围的数据在导出前及完成前核对当前范围，失效范围得到失败状态。B 将两份结果交给独立运行器的 --baseline-predictions、--learned-predictions；正式大模型只读取共同证据与公开 taxonomy。

首次及回流训练各自保存 training-run.json、模型描述符、artifact、dataset 和 job-records。新模型经验证后由管理员显式发布。真实客户端行为经既有上传、归档和冻结链路进入下一版数据，旧画像作为 derived_profile 追溯；固定 test 用户继续用于独立推断和对比。

## 真实 YARN 作业与资源证据

每个阶段在提交与完成时记录 job、application、driver、输出路径和资源配置。job-records 保留 submitted/finished 回执，失败或取消也记录。训练运行文件与导出清单包含实际作业索引；local 运行明确标记。

将实际 training-run.json 或导出 run-manifest.json 取到本地后读取证据：

```bash
python3 tools/collect_model_run.py \
  --run /path/to/run-manifest.json --output /path/to/新的证据目录 \
  --resource-manager http://实际RM地址:8088 \
  --history-server http://实际历史服务地址:19888 \
  --name-node http://实际NameNode地址:9870 \
  --inventory deploy/ubuntu/inventory.actual.json --require-parallel
```

采集器只查询清单内作业，保存 ResourceManager、HistoryServer 和 NameNode 原始响应、任务与 attempt、耗时、memorySeconds、vcoreSeconds。跨节点并行证据要求同一作业内不同节点的成功 attempt 有实际时间重叠。History 尚未可读、记录缺失或只执行 local 时保留 incomplete；后续采集到新目录，不覆盖旧失败记录。当前节点在线情况与历史并行结论分别保存，HA 状态保留 not_run。

接口遵循 [Hadoop 3.4.2 HistoryServer REST](https://hadoop.apache.org/docs/r3.4.2/hadoop-mapreduce-client/hadoop-mapreduce-client-hs/HistoryServerRest.html) 和 [ResourceManager REST](https://hadoop.apache.org/docs/r3.4.2/hadoop-yarn/hadoop-yarn-site/ResourceManagerRest.html)。正式验收还核对所用输入及模型依赖的摘要可读、实际节点与资源预算，以及公开项目、合成样本、真实客户端回流各自数量。

## 指定任务取消、接续和恢复

管理员先读取明确任务及当前 attempt：

```bash
/opt/happygit/bin/data-platform learning-task \
  --namespace experiment-固定命名空间 --id 任务ID --action show
/opt/happygit/bin/data-platform learning-task \
  --namespace experiment-固定命名空间 --id 任务ID \
  --action cancel --attempt 已观察到的尝试次数 --reason 实际原因
```

queued 任务可直接取消；运行任务先变为 cancelling，worker 检查原租约和取消状态，并只终止自己为该任务提交的作业。模型登记、画像发布前再次检查，个人推断队列保留取消状态。取消或失败后，将 action 改为 retry，携带最新 attempt 和原因，创建关联原任务的新任务。原任务、旧尝试和输出保留，新尝试从相同冻结输入重新计算。

进程异常退出后，原 ZooKeeper 会话释放租约，新 worker 在独立 token 目录接续。旧驱动失去租约时停止自己持有的作业。进程被强制终止而来不及退出作业时，根据回执中的确切 applicationId 查看或取消残留应用，再继续任务。模型或输入范围已变化时重新冻结和调度当前输入。管理台任务详情显示实际作业、阶段、操作原因，并将取消和接续操作绑定任务及 attempt。

控制台 status 与业务 learning/status 返回 releaseId、sourceCommit、nodeConfigSha256，供核对部署代际。服务操作要求明确单元：

```bash
sudo python3 tools/server_release.py service \
  --node-config /opt/happygit/current/nodes/hg-1 \
  --action status --unit happygit-collector.service
```

action 支持 start、stop、restart，只操作所选节点 roles.json 声明的单元；多个单元使用多个 --unit。变更操作在数据根 operations 保存返回码和结果。已有 VERSION 的 HDFS 节点按既有角色恢复，不再次格式化。故障演练在隔离环境针对明确服务和输入执行，保留失败任务、旧模型、发布指针和读取证据。
