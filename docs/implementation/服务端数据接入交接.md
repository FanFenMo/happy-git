# 批量采集与云端行为接入交接

开发基线为 develop `5e46112c8140b0a650ada8e8d0eb10e8802d45e5`，分支 `feature/data-and-cloud-ingest`。本轮实现服务端与数据平台，客户端、数据集及实验工具由另一成员维护。原有 README、设计说明和未提交方案资料不纳入本轮提交。

协议提交为 `69f1b5c`，服务端功能提交为 `fb1c54f`，数据平台功能提交为 `30152e3`；最后另有部署与交接文档提交。完整最终分支头以本轮PR和 `git log -1` 为准。

实现沿用现有 Java MapReduce、HDFS 与 ZooKeeper 任务系统。Spring Boot 新增独立 cloud profile、MySQL/Flyway、云端 OAuth 身份、应用会话、绑定设备、事务事件接收、集合快照和偏好/清理接口。[云端接入协议](云端接入接口.md)是客户端适配入口；本轮没有实现训练、画像和搜索计划 API。

公开采集增加有请求预算的计划。管理员以 `deploy/ubuntu/collection-plan.example.json` 为模板指定跨语言、主题、关注度和归档状态的查询、种子及可选公开用户。计划保存在 ZK，查询每页独立任务，公开集合按页保存接续位置；元信息与 README 使用持久 ETag/Last-Modified 缓存，记录检查时间、响应状态和限流信息。请求预算包含失败重试与304，暂停或耗尽后不继续发起请求，当前在途请求可能完成。相关项目在计划内去重补抓，公开集合读取不到标记 unknown，超过20页标记不完整。

```bash
bash data-platform/bin/data-platform plan --file deploy/ubuntu/collection-plan.example.json
bash data-platform/bin/data-platform worker --id hg-1
bash data-platform/bin/data-platform status
bash data-platform/bin/data-platform plan-control --id public-catalog-20261108 --action pause
bash data-platform/bin/data-platform plan-control --id public-catalog-20261108 --action resume --extra-budget 200
bash data-platform/bin/data-platform export-catalog --namespace public --output /path/to/frozen/catalog.jsonl
```

冻结目录仅包含最新观测为公开的 repository，保留实际 repoId、语言、topics、描述和可获取 README。缺失 README 保持 missing。输出 JSONL 与 `.manifest.json`，清单记录输入提交任务、HDFS路径、计数、字节数和输出 SHA-256/catalogSnapshotId；拒绝覆盖已有文件。管理工作台 `/` 可导入计划配置、暂停/接续、查看状态计数和实际语言/topic观测，并导出相同语义的目录文件。任务详情显示归档路径与摘要，云端归档使用独立任务类型。

MySQL 部署使用 `deploy/compose.yaml`，或在 Ubuntu 准备 MySQL8数据库并设置 `deploy/ubuntu/cloud.env.example` 中的私有配置。业务服务需要 JDK17，数据平台继续使用 JDK11。`cloud` profile 启动时执行 `server/src/main/resources/db/migration/V1__cloud_identity_and_ingest.sql`；无 cloud profile 时保留现有热门/授权运行方式，不加载业务数据库。MySQL应使用事务存储，备份数据库和密钥配置，数据库端口不暴露公网。OAuth 应用要允许 cloud 回调地址；现有本机网页授权地址独立保留，必要时为云端身份使用允许该回调的独立 OAuth 应用。

```bash
# 配置由维护者填写并通过私有 EnvironmentFile 注入。
java -jar server/target/happygit-server-1.0.0-SNAPSHOT.jar --spring.profiles.active=cloud
# 数据平台环境额外配置 HG_CLOUD_API_URL 和 HG_CLOUD_ADMIN_TOKEN。
bash data-platform/bin/data-platform archive-cloud --namespace cloud-real
```

archive-cloud 每次准备一个冻结批次并交给现有 worker。可由 `happygit-cloud-archive.timer` 周期提交；这些 systemd 文件需由维护者按现有安装路径手动安装。worker先闭合HDFS文件，再用服务凭据提交摘要和范围，业务服务核对后推进exportedThrough。旧范围失效时拒绝提交；已接受的事件与ACK保留最小稳定身份。processedThrough仍为0，后续画像发布再推进。`process` 拒绝直接混合 cloud-export 历史，第二轮须从有效scope及冻结数据组装去重快照，避免重复subject种子或重新使用失效范围。

分析关闭或清理会移除MySQL事件正文和集合，清空待归档正文并使HDFS历史范围失效；已生成HDFS文件的物理清理由部署维护者结合保留策略执行，本轮不自动删除历史归档文件。旧范围不能直接用于后续训练。内部analysis-scopes只列出当前允许的subject/epoch，结果发布前也必须再次核对。真实生产与合成实验使用不同namespace，私有观测仅保留原有最小可见性墓碑。

本轮开发分支只做必要编译和实现自查，不执行功能或集成测试。server以release17、data-platform以release11编译通过，管理端内联脚本通过node --check，git diff --check通过；没有运行测试套件、数据库迁移或业务请求。编译使用本机JDK25与Maven3.9.16，不代表已在生产JDK11/17运行验收。集中验收在合入develop后检查真实OAuth身份、重复发送与冲突、关闭分析后的旧范围拒绝、不完整集合不覆盖、归档失败不推进水位及客户端有效浏览到HDFS的整条链路。

当前环境的WSL因Hyper-V不可用而无法启动；本轮没有实际配置的MySQL业务库、GitHub云端OAuth应用或可访问HDFS运行环境。因此没有本轮真实批量目录、持久ACK或归档证据，240项目pilot目录待部署采集后交付。维护者需补齐Ubuntu主机、公开采集访问凭据和云端身份配置，再提供实际服务地址供客户端成员联调。任务接口与导出命令已具备代码，开发完成、编译通过和业务验收分别记录。
