# HappyGit 接口与模型契约

日期：2026-11-08。本文用于两人并行开发，描述待实现契约。当前代码已存在的入口与新增能力分别说明，字段变更先更新本页，再修改两端实现。整体位置见[项目方案](项目方案.md)。

## 数据与版本边界

当前离线输入继续使用repository、subject、collection和event四类JSONL。详细类型与现有去重规则沿用[服务端数据集规范](../../数据集生成要求-服务端版.md)。原始公开来源、合成用户、真实客户端回流和独立评测数据分开登记，来源属性随归档和训练清单保留。

| 标识 | 负责回答的问题 | 使用范围 |
| --- | --- | --- |
| datasetVersion | 本次选中了哪些数据 | 初始数据、回流批次、训练与评测清单 |
| catalogSnapshotId | 用的是哪批项目快照 | 向量、训练、推断和引用资料 |
| featureSpaceVersion | 向量坐标和投影规则是哪一版 | 同版词表、IDF、Java和客户端投影 |
| modelVersion | 使用哪次训练得到的模型 | 模型制品、画像和实验结果 |
| generationId | 本次对个人数据生成的结果是哪一批 | 画像、搜索计划、群体统计和处理进度 |
| inputId | 客户端本次计算使用哪个冻结输入 | 本地排序提交、账号和缓存版本核对 |
| analysisEpoch | 用户当前允许分析的数据范围是哪一代 | 数据上传、云端清理和结果有效性 |

同一个模型版本可生成多个generation。模型换版时建立新的modelVersion；新特征空间需要重新投影相关样本，不能混用旧坐标。datasetVersion表示不可变选择快照，底层持续新增资料时产生后续版本。

## 业务服务与客户端

新增业务接口统一位于`/api/v2`。现有`/api/platform`管理预览接口保留其运维职责，不承担个人业务认证。下表是待实现接口，不是当前可调用接口清单。

| 业务 | 建议路径 | 输入与结果 |
| --- | --- | --- |
| 云端登录 | `/auth/github/begin`、`/auth/github/callback`、`/auth/github/poll` | 由服务端核验GitHub身份后建立应用会话；客户端不自行声明可信账号 |
| 会话恢复与退出 | `/session/refresh`、`/session/logout` | 应用凭据轮换和撤销，由原生模块保存凭据 |
| 设备注册 | `/devices/register` | 建立账号所属设备流，返回权威序号与分析版本 |
| 有效行为接收 | `/events/batches` | 批量事件、流序号和摘要；返回acceptedThrough |
| 集合快照同步 | `/me/collections` | Star/owned快照、完整性和修订；不完整输入不覆盖旧完整代 |
| 分析设置与清理 | `/me/preferences`、`/me/analysis/reset` | 明确设置值、期望修订和操作身份，更新分析版本 |
| 个人画像读取 | `/me/portrait` | 返回当前generation或pending/stale等实际状态 |
| 搜索方向读取 | `/me/search-plan` | 返回同代画像生成的结构化搜索条件及少量示例候选 |
| 群体结果读取 | `/cohorts` | 聚合技术分布、样本数、来源和计算时间 |

客户端默认保留本机GitHub网页会话。云端应用会话独立核验身份，首次开启分析时绑定；恢复或换号时核对两者一致。浏览历史本地记录与云端上传使用独立设置，关闭云端分析后停止后续上传并更新云端结果可用状态。

SQLite升级保留既有账号、历史与集合。新增逐次事件、上传队列、云端状态、画像缓存和可信计算输入。设备流中的每个有效浏览有稳定eventId与递增deviceSeq；同身份重发相同内容得到原回执，不以重试次数增加行为权重。每批最多500条并有请求体上限，具体编码复用旧统一契约中已有的确定性摘要规则。

上传事件的subjectId由应用会话决定。发生时间、项目标识、来源及设备序号由原生层冻结，页面只提交业务动作。服务端接收成功后返回acceptedThrough，归档后记录exportedThrough，新画像实际使用后发布processedThrough。三个进度分别保存。

有效浏览在原生记录聚合历史的同一事务中生成：30秒内重复打开可以更新最近访问时间，但不额外增加有效计数或新增训练事件。客户端的trending、history、stars等入口来源可另存entrySource；导出到当前离线event时，source统一规范为browse或repo_open，避免被当前EvidenceReduce当作未支持的活动忽略。

Star与本人项目采用快照和修订，不伪造为浏览事件。隐藏/解除隐藏使用明确布尔值和幂等操作身份，及时影响本地候选；训练准备也读取当前有效反馈。清理云端数据使旧分析范围和相关结果失效，旧上传队列不能重新灌回已清除数据。

## 画像与搜索计划

画像外层包含subjectId、modelVersion、featureSpaceVersion、catalogSnapshotId、generationId、referenceTime、generatedAt、inputVersions、processedThrough和coverage。profile保留languages、topics、topInterests、证据项目及模型学习到的方向权重。证据不足时保留空分布和明确状态。

方向权重用于排序和解释，不命名为喜欢概率或职业概率。兴趣中心的代表项目不直接充当用户浏览证据；evidenceRepos必须引用该用户本次输入实际可用的项目。画像记录保留输入摘要和来源，便于后续回流分析。

search-plan与画像generation一致，每个查询包含topics、language、keywords、sort和排除条件，客户端根据固定规则构建GitHub搜索请求。默认一次最多4个查询、总计最多8页，继续浏览可产生下一轮有界任务。计划携带模型和画像版本，不包含任意脚本或可执行URL。

结果可以附少量已知项目作为示例或补充。客户端新搜索项目使用标准Repository DTO保留repoId、fullName、htmlUrl和原始字段，特征作为附加部分。未知特征保持缺失，不把训练目录之外的项目判定为无法推荐。

本机计算输入一次冻结账号上下文、画像版本、候选缓存版本、当前时间、近期未覆盖事件及隐藏项。只对processedThrough尚未包含的行为计算长期画像之外的本机增量，接收ACK不提前终结该增量。提交排序结果前核对输入仍有效，换号、删除、画像更新和新隐藏会阻止旧结果覆盖。

## 训练、推断与回流任务

数据平台分为数据准备、训练、推断和发布四种业务步骤，复用已有任务租约。当前`import`和`process`是已有命令，后续训练、模型加载与发布入口由甲实现；在落地前不提供伪装可执行的命令示例。

初始训练读取固定目录及训练用户，拟合特征空间、生成用户表示并学习兴趣中心。验证阶段选择参数后保存候选模型，模型制品包括分词规则、词表/IDF、中心、配置、数据及代码摘要。使用确定性随机种子，迭代次数和收敛条件纳入配置。

个人推断读取已发布制品并处理用户当前有效数据，结果输出到本次尝试的独立目录。训练中的候选版本不影响当前推断。用户数量超出单任务内存预算时按稳定用户块执行；固定目录的公共制品共享，用户结果按块导入。

回流记录把原始事件、集合和对应画像关联起来。旧画像属于derived_profile，至少记录subjectId、modelVersion、generationId、inputDigest和generatedAt；它用于变化分析与回归核查，不能被当前四类输入读取器误当成subject、event或人工标签。

训练样本准备从原始可用证据重建，记录所用时间范围、账号授权范围、数据来源及采样规则。新候选模型使用历史代表样本和新增数据；暂不直接把derived_profile作为监督目标。若以后加入弱标签，增加显式labelSource及对应协议，保持测试参考独立。

| 状态 | 允许的后续动作 |
| --- | --- |
| preparing | 汇总与冻结数据，尚未运行训练 |
| training | 记录实际作业及运行参数，当前线上模型继续服务 |
| candidate | 制品齐全，等待验证与可读性检查 |
| validated | 已有同口径验证结果，管理员可以发布 |
| active | 供后续个人推断使用，并保留发布记录 |
| retired | 退出当前使用，保留来源与历史结果引用 |

失败任务单独记录失败状态和实际原因，当前active模型保持不变。模型发布原子切换活动指针；画像发布原子切换generation指针。回滚模型指针后，已有画像仍标注实际生成它的版本，按需重新排队，不直接把历史画像改名。

## 数据库与所有权

MySQL按应用身份、事件接收、数据归档、模型训练和画像发布五组组织表。甲拥有服务端迁移文件，迁移按语义名称和版本顺序维护。乙根据本文实现客户端存储和协议，不同时修改服务端迁移；涉及跨端字段的修改先在本页约定。

画像快照及训练任务的元数据保存在MySQL或现有任务登记中，大规模正文与制品保存在HDFS，客户端缓存保存在SQLite。模型和结果正式发布只在对应制品完整、版本一致且输入授权仍有效时执行。检查限定于这些业务关系，不扩展成无关环境检测。

真实生产与合成实验的身份、数据目录、发布指针和运行报告分开。合成行为不触发真实GitHub写操作。实际使用数据参与训练时保留来源与数量，在报告中与初始合成样本分别统计。
