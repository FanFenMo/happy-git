# 画像训练、推断与回流入口

本轮服务端代码包含数据冻结、MapReduce 球面聚类训练、固定模型推断、模型与画像指针、回流调度。运行入口位于 `data-platform/bin/data-platform`，需要已构建的 JAR、JDK 11 和 Hadoop。业务服务使用 JDK 17 及 MySQL，数据库迁移包括 `V2__portrait_learning_loop.sql`。管理员凭据通过既有环境配置提供。

数据准备使用 `learning-prepare --dataset <dataset-manifest.json> --namespace <命名空间> --output <新快照目录> --include-cloud false`。输入数据包须包含 `canonical/repositories.jsonl`、`subjects.jsonl`、`collections.jsonl`、`events.jsonl` 与 `splits/subjects.jsonl`，并在 manifest 的 files 中登记各文件的 SHA-256。返回值是冻结数据描述符，指向 `dataset.json`。`--include-cloud true` 另读取已授权、已归档的客户端证据及当前修订；固定测试用户仍留在 test。

训练命令为 `learning-train --file <请求JSON> --output <新训练目录>`。请求的基本结构如下；dataset 值直接使用上一步返回的描述符。实验项目使用 `experiment-` 命名空间，合成项目目录不能登记为 production。

```json
{
  "namespace": "experiment-pilot",
  "registerModel": false,
  "dataset": {"path": "hdfs://hg-1:8020/path/dataset.json", "sha256": "实际摘要"},
  "seed": 20261103,
  "maxIterations": 12,
  "tolerance": 0.00001,
  "centerCounts": [4, 8],
  "directionBlends": [0, 0.25, 0.5],
  "behaviors": [{"browseHalfLifeDays": 30, "starWeight": 3, "ownedWeight": 1.5}]
}
```

训练只拟合 train 的用户表示与兴趣中心，使用 validation 在过去证据与留出近期证据之间选择配置。validation 没有同时具备两侧证据的用户时，训练不会产生可发布模型。test 不参与拟合或选参。训练目录保存 `artifact.json`、`model-descriptor.json`、候选配置和作业记录；制品包括固定词表/IDF、中心、行为参数、来源和验证摘要。返回值是模型描述符。

文件推断使用 `learning-infer-file --file <请求JSON> --output <新推断目录>`。请求的 model 为训练返回的完整模型描述符；manifest 包含 namespace、referenceTime、datasetKind 和 files，files 中列出目录与所选用户原始证据文件的 path/sha256。推断加载模型中固定的目录与特征空间，不重新拟合。返回的 profiles 指向分片目录；合并其中 `part-*` 即可交给 `tools/experiments/run_experiment.py --learned-predictions`，每行保留实际模型版本与证据引用。

生产训练默认登记模型但不自动发布。`learning-model --action status` 读取当前模型，`--action publish --file <发布请求>` 发布已验证候选，`--action rollback --file <回退请求>` 切回曾发布版本。发布请求包含 namespace、modelVersion、expectedRevision 和实际 reason。当前模型换版后，服务端将允许分析的账号重新排队，旧画像仍标记其原模型。

`learning-schedule` 冻结已闭合归档并提交个人推断任务。`learning-submit --file <训练请求>` 使用现有任务租约提交训练，`learning-batch --file <批次配置>` 按新增事件与时间间隔准备下一版候选；示例配置在 `deploy/ubuntu/learning-batch.example.json`，相关 systemd service/timer 须部署后启用。回流从原始事件和集合重建训练样本，旧画像仅作为派生状态追溯，不直接充当正确标签。

业务客户端读取 `/api/v2/me/portrait`、`/me/search-plan`、`/feature-spaces/{featureSpaceVersion}` 和 `/cohorts`。画像同时提供 state 与客户端 status，processedThrough 按 streamEpoch 列出，原生层仅取当前设备流进度。特征空间下载返回参与摘要计算的原始投影对象，其中 dictionary 是供客户端使用的词表。搜索计划与画像 generation 一致，并以 queries 直接返回；群体响应包含来源、实际样本数和 cohorts，少于十人的分布继续抑制。

集中验收使用独立 MySQL、原生 SQLite 和本地 MapReduce 的小规模测试数据。测试训练制品与生产目录分开，正式采集目录上的完整训练、真实账号操作、多节点训练和通用大模型对照另按第三轮执行。具体通过项与环境以本轮 validation 记录为准。
