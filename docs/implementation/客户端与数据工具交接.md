## 一、前置契约修复（`bugfix/recommendation-contract`）

针对 `develop` 分支中客户端本地推荐与评测契约存在的回归问题完成了修复，并合入 `feature/dataset-and-client-events`：

1. **召回查询规划契约对齐（`planDiscoveryQueries`）**
   - `client/shared/recommendation/recall.js` 返回带不可枚举 `.queryPlan` 自引用属性的查询数组，同时兼容直接按数组遍历（如测试套件与评测脚本）和解构 `{ queryPlan }` 的调用方。
   - 同步对齐 `client/src/services/discovery.js`、`client/src/stores/feed.js`、`client/electron/ipc-router.cjs` 与 `client/android/app/src/main/java/com/happygit/app/nativebridge/HappyGitPlugin.java`。
2. **仓库特征提取字段保留（`extractRepositoryFeatures`）**
   - `client/shared/recommendation/features.js` 在输出归一化 `tfidfVector`、`languageSet`、`topicSet` 的同时完整保留输入 Repository DTO 的全部原始字段，确保直接把提取结果传入 `scoreCandidate` 时能正确读取 `stargazersCount`、`updatedAt`、`ownerLogin` 等信息。
3. **兴趣画像与候选打分词项同构（`buildInterestProfile` / `scoreCandidate`）**
   - `client/shared/recommendation/profile.js` 在聚合用户画像时保留 `topicWeights`、`languageWeights` 与 `termWeights`（含 `topic:*`、`lang:*`、`owner:*`、`text:*`），`client/shared/recommendation/rank.js` 与 `client/src/workers/recommendation.worker.js` 支持与候选仓库 `tfidfVector` 进行同构余弦相似度计算，并在存在匹配特征时稳定产出推荐理由标签。
4. **MMR 重排与滑动窗口多样性约束（`rerankCandidates`）**
   - 移除 `scoredCandidates.length <= limit` 时跳过重排的早退逻辑；即使候选数量不超过 `limit`，也严格执行 MMR 边际相关性重排以及滑动窗口（窗口大小 10）内同作者最多 2 个、同语言最多 6 个的硬性约束。
5. **原生推荐快照与修订号校验（`createSnapshot` / `commitRecommendation`）**
   - 在 Windows (`client/electron/database-worker.cjs`) 与 Android (`HappyGitDbHelper.java` / `LocalRepository.java`) 新增 `recommendation_snapshots` 表，持久化 `input_id`、`account_id`、`purpose`、`input_versions_json` 与 `consumed` 状态。
   - `commitRecommendation` 校验快照存在性、`purpose` 一致性、单次消费（防止重复提交同一 `inputId`）以及与 `account_revisions` 当前修订号的一致性；任一不匹配均返回 `{ ok: false, error: 'INPUT_CHANGED' }`。

## 三、双端 SQLite v3、按次行为事件队列与云端同步

### 3.1 SQLite v3 迁移与新增表结构

Windows (`client/electron/database-worker.cjs`) 与 Android (`client/android/app/src/main/java/com/happygit/app/nativebridge/HappyGitDbHelper.java` + `LocalRepository.java`) 均已升级至 `user_version = 3` / `DATABASE_VERSION = 3`，保留全部 v1/v2 历史表数据，并新增：

1. `cloud_account_state`：存储云端 `subject_id`、`device_id`、`stream_epoch`、`analysis_epoch`、`analysis_enabled`、`cloud_bound`、`cloud_account_id`、`session_expires_at`。
2. `local_activity_events`：存储本地按次浏览行为明细（`event_id`、`account_id`、`repo_id`、`record_kind`、`source`、`entry_source`、`occurred_at`、`effective_at`、`time_flag`、`analysis_epoch`）。
3. `event_outbox`：存储待上传事件队列（复合主键 `(account_id, stream_epoch, device_seq)`，含 `event_id`、`analysis_epoch`、`record_kind`、`payload_hash`、`acknowledged` 等）。
4. `local_sync_state`：维护设备单调递增序号与三类水位（`next_device_seq`、`accepted_through`、`exported_through`、`processed_through`、`in_flight_request_id`、`last_error_code`、`retry_at`）。
5. `cloud_collection_sync`：维护 `stars` 与 `owned` 集合快照在云端的同步修订号 `synced_revision`、`synced_complete` 与 `synced_hash`。
6. `client_mutation_outbox`：本地变更队列预留表。

### 3.2 核心业务与安全规则实现

- **按次浏览去重与双写一致性**：
  - `recordBrowse` 保持 30 秒内同一仓库重复打开不累加 `visit_count` 的口径；
  - 仅当 `visit_count` 发生真实递增且 `history_enabled = 1` 时，在同一 SQLite 事务内写入 `local_activity_events`；若同时满足 `analysis_enabled = 1` 且仓库为公开仓库，则在同一事务内分配连续递增的 `device_seq` 写入 `event_outbox`。
- **删除/清空浏览历史的 `discard` 墓碑转换**：
  - 调用 `deleteHistory(accountId, repoId)` 或 `clearHistory(accountId)` 时，除删除 `browse_history` 与 `local_activity_events` 外，将 `event_outbox` 中尚未被服务端确认（`acknowledged = 0`）的对应 `open` 事件原地转换为 `recordKind = "discard"`，清空 `repo_id`/`source`/`occurred_at` 等敏感载荷并重算 `payloadHash`，从而既抹除未上传的浏览内容，又严格保持 `deviceSeq` 连续不断裂。
- **Payload Hash 跨端严格对齐**：
  - `client/shared/contracts/index.js`、`client/electron/database-worker.cjs` 与 Android `LocalRepository.java` 的 `open` 事件哈希算法与服务端 `IngestService.openHash` 完全一致：
    ```json
    ["1.0.0", eventId, streamEpoch, deviceSeq, analysisEpoch, repoId, occurredAt, source]
    ```
    对其 UTF-8 JSON 字符串计算 SHA-256 小写十六进制摘要。
- **账号一致性门禁与加密凭据存储**：
  - `client/electron/cloud-service.cjs`（使用 Electron `safeStorage` 加密存储）与 Android `CloudService.java`（使用 Android Keystore `AES/GCM/NoPadding` 加密存储）在每次上传前强校验 `cloudSession.accountId === localAccountId`；若不一致立即阻断上传并返回 `CLOUD_ACCOUNT_MISMATCH`。
- **三类水位严格区分**：
  - `acceptedThrough`：服务端已接收落库的最大 `deviceSeq`（用于确认本地 `event_outbox`）；
  - `exportedThrough`：服务端已导出到 HDFS Raw 区的最大 `deviceSeq`；
  - `processedThrough`：离线画像作业真正完成消费的最大 `deviceSeq`（客户端绝不把上传 ACK 的 `acceptedThrough` 伪装成 `processedThrough`）。
- **设置页三权分立（`client/src/components/SettingsModal.vue`）**：
  - 清晰拆分：**本地浏览历史开关**、**云端兴趣分析与行为上传开关**、**清除范围选择（仅清除本地历史 vs 重置云端兴趣分析数据与画像）**，并实时展示待上传队列条数与 `acceptedThrough` / `exportedThrough` / `processedThrough` 水位。
