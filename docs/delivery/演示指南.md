# HappyGit 端到端项目演示指南

本指南按第三轮交付规范组织干净启动后的四段式完整演示链路：**查看数据来源和首版模型 → 客户端产生行为 → 离线画像与搜索 → 回流训练及下一版发布**。

> **演示真实性原则**：长耗时 Hadoop MapReduce 离线训练与全量采集可以展示**事先实际运行并持久化保存的历史任务记录**，并在界面与口头解说中明确指出记录时间与对应作业 ID，绝不将历史记录伪装成演示瞬间实时跑完的结果。

---

## 演示前准备检查

1. **服务端与数据平台（成员甲侧）**：确认业务 API（`/api/v2`）、MySQL、HDFS、YARN/HistoryServer 与数据管理台（Console）处于可读状态；核对管理台显示的 `releaseId`、`sourceCommit` 与当前活跃 `modelVersion`。
2. **双端客户端（成员乙侧）**：
   - Windows 端安装或启动对应提交构建的 `HappyGit.exe`（`v1.2.0`），确认 `electron/config.generated.json` 已预置公开 HTTPS 业务地址（普通用户无需输入任何地址或密钥）；
   - Android 端安装对应 `HappyGit-v1.2.0.apk`（`versionCode=3`），演示旧版覆盖升级时提前保留一台存有旧浏览历史的设备。
3. **测试账号与安全边界**：
   - 使用明确的演示 GitHub 账号；
   - 若演示真实 `Star / 取消 Star`，**仅在事先明确指定的测试仓库**上操作，记录起始状态并在演示结束前恢复初态。

---

## 第一段：查看数据来源与首版模型

1. **展示数据来源与目录冻结**：
   - 打开数据管理台或查看数据清单文件（`dataset-manifest.json` / `provenance.jsonl`），分别说明：
     - **真实公开 GitHub 采集目录**（例如 2026-11-17 审计的 51 批导出、去重后 75,129 个公开仓库、73,631 份非空 README 及保留的 7 项缺口）；
     - **合成对照用户与真实客户端回流用户**严格分离登记，不混算为同一数据来源。
2. **查看首版模型与历史训练记录**：
   - 在管理台或模型状态命令（`learning-model --action status`）展示当前活跃的首版模型版本号、`featureSpaceVersion`（64 位 SHA-256）、`catalogSnapshotId`、验证选参摘要与实际 YARN/MapReduce 作业记录。
   - **明确标注记录时间**：如展示提前完成的集群训练记录，口头和界面同步指出“该训练作业实际执行于 `<记录日期时间>`，耗时 `<实际秒数>`，当前处于已完成历史记录状态”。

---

## 第二段：客户端产生真实个人行为

1. **登录与双会话核对**：
   - 在 Windows 或 Android 客户端打开登录弹窗，通过原生 GitHub 网页窗口完成本地账号登录，展示公开仓库与 Star 自动同步。
   - 进入**设置 → 2. 云端兴趣分析与行为上传**，点击“绑定云端会话”完成同账号云端授权，展示“已绑定同账号会话”与初始 `Analysis Epoch #1`、待上传队列 `pending`、三水位 `accepted / exported / processed`。
2. **产生有效浏览与反馈回流**：
   - 在**发现项目**页面点击并打开 2–3 个不同方向的公开仓库（同仓库间隔 `> 30s` 才新增有效浏览计数与事件，快速连点同仓库可顺带演示 30s 去重不会虚增事件）；
   - 可在指定测试仓库点击 **Star**（触发 `/api/v2/me/collections` 修订上传，演示结束后恢复）；
   - 在推荐卡片点击 **隐藏**（写入显式负反馈并同步至 `/api/v2/me/preferences`），随后进入**设置 → 4. 已隐藏的推荐仓库**展示可追踪的隐藏列表与“恢复推荐”按钮。
3. **查看事件上传与三水位分离**：
   - 返回设置页点击“立即上传”（或观察自动刷新），指出 `pending` 归零且 `acceptedThrough` 递增，而此时 `processedThrough` 仍停留在旧值，证明上传确认与离线消费进度严格分离。

---

## 第三段：离线画像发布、有界搜索与近期排序

1. **触发或查看个人离线推断与画像发布**：
   - 在服务端执行归档与个人离线推断调度（`learning-schedule`），待新 `generationId` 发布且 `processedThrough` 推进覆盖刚上传的 `deviceSeq`。
2. **客户端刷新同代云端画像与搜索方向**：
   - 切换至客户端**个人空间**页，点击“刷新云端画像”，展示：
     - 画像状态由 `pending` / `stale` 变为 `ready`；
     - 显示当前 `modelVersion`、`generationId`、学习到的兴趣方向权重与可追溯的个人 `evidenceRepos`（仅引用本人输入，不混入模型代表项目）；
     - 切换至**群体分布**独立页签，展示聚合语言/主题分布、来源标注与少于 10 人时的 `<10` 抑制提示。
3. **验证画像驱动有界搜索与本机增量接续**：
   - 切回**发现项目 → 为你推荐**，展示画像方向生成的结构化有界搜索（单轮最多 4 查询 / 总计 8 页，可点击“探索下批项目”翻页，且可发现训练目录之外的真实 GitHub 项目）；
   - 展示项目卡片上的**用途线索**（及来源 `description/readme/topics`）、**README 安装线索**、**许可证**、**最近维护时间**以及标注为**“关注度 ⭐”**的 Star 数（明确不冒充质量评分）；
   - 再新打开 1 个未被当前 `processedThrough` 覆盖的新方向仓库并刷新推荐，观察该新事件立即作为本机近期增量参与排序并在 24h 内对已看项目降权，而此前已被 `processedThrough` 覆盖的旧事件不再重复累计。

---

## 第四段：回流再训练、下一版模型发布与独立评测报告

1. **查看回流训练清单与下一版模型发布**：
   - 在管理台展示上述真实客户端回流批次已被纳入下一版训练样本准备清单（保留与旧画像 `derived_profile` 的版本关联，但不把旧画像当作监督真值）；
   - 展示已完成验证的新候选模型记录（明确标注历史运行时间与新增样本规模，小样本时不声称效果普遍提升），演示管理员显式发布换版（`learning-model --action publish`）及必要时可回退旧版本指针（`--action rollback`）。
2. **客户端切换新代画像**：
   - 客户端刷新画像，确认页面与排序元数据已切换为新 `modelVersion` 与新 `generationId`，按更新后的方向继续搜索真实项目。
3. **展示独立画像对比实验报告**：
   - 打开 [第三轮画像对比实验报告](../experiments/第三轮画像对比实验报告.md) 及 SVG 图表，展示规则基线、学习模型（初版 vs 回流版）与独立通用大模型（20 用户×3 次重复波动 + 4 类匿名盲评核查）的冻结对比结果与已知边界。
